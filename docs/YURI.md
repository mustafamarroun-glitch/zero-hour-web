# Yuri’s Revenge integration

Added October 4, 2026. Zero Hour and Yuri use different original game engines. The website runs Zero Hour with New Shoes threaded WebAssembly and Yuri with RA2 VM, which executes player-supplied x86 executables using v86, custom firmware and a Win32/DirectX compatibility layer. Navigation is shared; assets, simulation and multiplayer protocols are separate.

## Import and play

Select Yuri’s Revenge in the header, enter a commander name, then import using the same setup as Zero Hour. Choose or drop one ZIP/RAR, select a complete game folder, or select its files. A containing folder is supported. The installer requires gamemd.exe, ra2.mix, ra2md.mix, language.mix, langmd.mix, BINKW32.DLL and Blowfish.dll; retain the rest of your maps/audio/resources. Encrypted and multipart archives must be extracted on your computer first. Launch loads the installed cache without a second runtime picker. Open Single Player → Skirmish. Original disk files are unchanged and nothing is uploaded.

Imported files use IndexedDB `zhweb-yuri-game-files-v1`, version 1, store `files`. `yr/<path>` Blob records and the separate `zhweb-library-manifest-v1` inventory commit atomically. A failed/cancelled replacement retains the previous game. Imports await the launcher's startup storage check, avoiding a lock race with quick folder/file selections. Existing compatible Yuri caches are validated before adoption. Quota is checked before installation; incomplete files never become a ready library. Cross-tab storage locks prevent replacement/removal while a game uses the files. Removal deletes only this installation and inventory, retaining custom maps, preferences and `zhweb-yuri-saves-v1`. Online-Games storage is never adopted. Zero Hour keeps its OPFS library; both titles share the website commander identity. Browser quota and clearing all origin data still affect both titles.

Settings use the shared controls and separate `zhweb-yuri-settings-v1` preferences. On the next launch, the adapter applies display/audio/scroll choices to runtime preferences and browser-local RA2MD.INI. Renderer choices map to Yuri's own effects setting; the engines remain different. ZIP backup preserves all installed files and can be imported directly. Saves are separate from that installation backup; keep your original files too.

Both **Get ZIP** and **Get RAR** open the user-supplied [Google Drive location](https://drive.google.com/file/d/1b7RaB8d0K1ydWofD5BEf7MXpkmaytnUX/view?usp=sharing). Access and remote archive contents could not be verified. The site does not fetch the retail files automatically. Acceptance used the actual local movie-free RAR and a nested DEFLATE ZIP made from the same installation: 166 files, music and 53 map files retained, with a required 10-byte empty movie MIX placeholder.

Save inside the game before Exit to website. Cancel retains the VM; confirm unloads it and restores focus to the launcher. Hidden masthead/footer controls are inert during gameplay. The shared website toolbar provides fullscreen, settings, diagnostics and exit. In Settings, Saves & maps provides native save export/import, custom maps and an opt-in performance recording. The duplicate engine sidebar and debug panel are hidden. Original game menus and native input remain intact.

## Multiplayer and deployment

Create room uses the shared `/rooms` service and generates an eight-character invite code. Copy invite shares `/yuri/?room=<code>`. Each player imports matching files. The service checks game, runtime and complete-content fingerprints and assigns a separate internal 96-bit relay code. The launcher passes `network=1` and `/yuri-<relay code>` to the engine. The code selects a virtual LAN, not an authenticated account. Enter **Network** in the original game; the host creates the native match, friends join and mark ready. Per-player RA2MD.INI preferences are excluded from content matching. Interrupted matches cannot resume.

`npm start` supplies the independent RA2 VM binary WebSocket relay with the existing allowed-origin checks. `/yuri-health` reports its health. Restart existing servers to load this addition. The checked bundle is `tools/yuri-relay/relay.cjs`; the Docker site stage includes it. A fresh Docker/engine rebuild was not rerun.

For static hosting, deploy this Node service behind TLS/WSS and configure `/rooms`, `/nostr` and `yuriRelay` in `network-config.json`. Yuri reads the explicit relay service address and appends `/yuri-<relay code>`; local hosting falls back to the room service's origin. HTTPS pages require WSS. Set `ALLOWED_ORIGINS` to the frontend HTTPS origin. Zero Hour retains its WebRTC gameplay path. The public preview uses a temporary Cloudflare service on this PC; it is not permanent hosting.
