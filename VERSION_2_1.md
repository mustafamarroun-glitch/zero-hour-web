# Zero Hour Web 2.1.0

Version 2.1 repairs browser-file removal and the original game's Exit Game button, and completes the reliability controls discussed for Version 2. The unchanged Version 2.0 source is preserved by commit `3954991`; a private checksum-verified Git archive is under `output/backups/Zero-Hour-Web-v2.0.0/`. The engine and decoder binaries remain pinned and unchanged. The `zero-hour-web-v1` namespace and existing preference keys remain compatible.

## Changes

- Remove installed game calls the actual managed-storage API. An exclusive, non-waiting lock prevents deleting files used by another game tab. The installation manifest is cleared only after filesystem deletion succeeds. Missing files are treated as already removed; permission and other failures keep the manifest for retry. Commander, settings, original files and stored saves are preserved.
- Clean leftover game files is available in Installed files & recovery and Settings, including before import. It removes abandoned installation, launch and extraction folders. It retains the authoritative installation, active roots, unknown folders and other products' storage. Results distinguish cleanup failures and files in use. Cleanup does not clear browser-wide storage or save databases.
- The original engine's quit event now runs the same bounded shutdown path as the website's Exit game control. The path stops save scheduling and the frame loop, performs a fresh final save flush, and destroys the runtime. Failed loop stopping uses verified worker termination before flushing. A stalled shutdown offers an explicit Force close action after 12 seconds and an automatic fallback after 60 seconds. Unconfirmed saves produce a visible warning; installed archives remain available for relaunch.
- Import shows Extracting archive, Validating files, Saving game files and Finishing installation stages. Cancellation is checked before committing the replacement manifest, including during OPFS saving. It preserves the previous installation and disables cancellation once the new installation has committed.
- Launch refreshes prepared archive paths from the validated current installation rather than reusing obsolete cached paths. Readiness errors identify missing/unreadable archives when available.
- Failed installed-file checks retain the manifest and archives, clear cached launch paths, and explain retry/replacement/removal. Settings provides those recovery controls even when startup cannot restore the library. An unreadable installation record blocks ambiguous leftover cleanup; explicit removal can reclaim allowlisted installation folders under exclusive locks.
- Importer source-permission and artwork databases now use product-specific names. The ambiguous legacy shared databases are left untouched. Engine-save paths and databases remain compatible with 2.0. Leftover storage totals now include inactive extraction folders.
- Actual size now caps both canvas dimensions while preserving the engine aspect ratio, keeping input coordinates aligned when either viewport dimension is smaller than the render resolution. Fit mode, real engine resolutions and existing audio/edge-scroll/renderer controls remain available.
- Diagnostics can be downloaded or copied. Reports include interface version, browser/isolation information, settings, library/storage summary, recent errors and bounded engine/renderer diagnostics. Unresponsive engine diagnostics still return a browser report. Clipboard refusal falls back to a download.
- Settings displays the interface version and checks the site's current version manifest on request. Applying an available update reloads the interface only after the game, room, import, backup and cleanup have finished. Local archives and saved data are not cleared.
- Settings retains a visible Close button while scrolling on desktop and narrow screens.

## Verification

`tools/verify-v21.cjs` passed in a disposable headless Windows Chrome profile using actual local game files. It verified deletion failure/retry, archive removal and reload, commander/stored-data/other-product preservation, full ZIP reimport, remembered installation, cancelled RAR and malformed ZIP replacement, active-root protection, leftover cleanup, the native Exit Game button, confirmed final save flushing, real Alpine Assault terrain, live 1600 × 900 rendering, copy/download diagnostics, update blocking during gameplay, protected toolbar exit and relaunch. A simulated final-save failure closed with a warning. There were no page errors or missing resources.

`tools/verify-v21-followup.cjs` passed cancellation during actual OPFS saving, responsive settings, three viewport sizes in Actual size mode, real mouse selection and builder movement, forced worker quiescence after a simulated loop-stop failure, visible Force close after an unresponsive shutdown, and successful relaunch/normal exit afterward. The first follow-up attempt raced website readiness and camera settlement; the verifier now waits for both. No product failure is attributed to that attempt.

`tools/verify-v21-storage.cjs` passed isolated regressions for transient read refusal, size mismatch, corrupt records, retry, cached-launch prevention, explicit Settings removal, legacy IndexedDB preservation, product-cache clearing, extraction-byte inventory and cleanup, and desktop/mobile recovery controls. These small fixtures test storage safety, not native gameplay.

`tools/verify-v21-upgrade.cjs` served the unchanged archived 2.0 site and current 2.1 at one origin in one fresh profile. It created an original-engine Alpine Assault save through the native Save/Load UI on 2.0, upgraded to 2.1, checked identical save bytes, preserved the installation/commander/settings and loaded the saved battlefield through the native Load menu. After explicit archive removal and full retail-folder reimport, the same saved match loaded again. Test-harness server restart and menu-navigation issues were corrected; they were not product defects.

Private reports are `.local/version-21-verification.json`, `.local/version-21-followup-verification.json`, `.local/version-21-storage-verification.json` and `.local/version-21-upgrade-verification.json`; captures are under `output/playwright/v21-*`. Native save creation/load and fresh shutdown flushing were verified separately. Physical Mac, audible playback and completed matches on separate internet networks remain separate acceptance gates. Multiplayer reconnection, replays, custom keybindings and fabricated graphics presets are outside this release.

The GitHub Pages workflow checks and packages the release before publication. The acceptance results above concern local verification; hosted deployment checks are recorded separately.
